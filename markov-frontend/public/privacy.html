Data & privacy.

This page describes how the current Markov-cero frontend handles account access and solver submissions. It reflects the implementation in this project.

Account access

Email signup, confirmation, sign-in, and account records are handled by Supabase Auth. The frontend stores the signed-in session in this browser’s session storage, which is cleared when the browser session ends or you sign out. The frontend never needs a Supabase service-role key.

Models and results

The public pages can be read without an account. In the workspace, you may paste or choose an MPS or LP model. The model stays in the browser until you submit it. When a solver API URL is configured, submitting sends the model and your access token to that API. The current frontend does not persist models or solver results to a database.

Solver limits

The API adapter verifies access with Supabase before invoking the solver. It limits model input to 1 MB, permits at most two concurrent solves, sets a solver time limit, and uses temporary files for each run. The temporary directory is removed after the request completes.

External links

Documentation, status, and issue links open the project’s GitHub repository. Those services have their own handling of visits and account data. The design file is maintained in Figma.
