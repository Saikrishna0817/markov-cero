# SIH 2026 Implementation Audit

**Date:** 2026-09-28  
**Scope:** Current implementation against `implementation_plan.md`, actual RTX 2050 GPU evidence, current ML collection/training evidence, and the registered CTest suite.  
**Disposition:** Useful prototype with substantial numerical and product work completed; not yet ready to claim commercial-solver parity. W2 remains open by the user's acceptance rule. The GPU QP x-update remains incomplete; real RTX 2050 measurements were completed before any scope decision.

This is a findings register, separated by review perspective. “Pass” means only the evidence named here; it does not imply parity with CPLEX, Gurobi, Xpress, or SCIP.

## SIH evaluator review

1. **Acceptance claims must stay narrow.** The solver has meaningful end-to-end capability across LP/MILP/QP/NLP/MINLP and verified GPU paths, but large-scale commercial competitiveness is not established. Present the GPU result as an experimental, correct path whose measured cases lost to CPU PDLP.
2. **ML has a narrow node-count signal, but no validated solve win.** Candidate ONNX on MIPLIB `cvs16r128-89` scored 6,865 candidates across two calls (maximum 3,472 in one call) and explored 4 vs 6 nodes in two matched 15-second trials. Both were `ResourceLimit` with no incumbent; the model has no held-out test instance and the committed artifact remains invalid. Do not claim an ML solve or performance win.
3. **Benchmark representativeness and timing fairness are weak for performance claims.** The final-binary 20-case HiGHS comparison has two repeats per solver and fixed one/four-thread markov-cero settings; all 20 objectives agree, but markov-cero is slower and the process/API timing boundaries differ. The broader 23-case W9 report remains one-shot and includes more failures. All 255 checked-in local Netlib/MIPLIB/Mittelmann/QPLIB cases now have a final-binary 15-second sweep, but this is shorter than the plan-level 300-second caps and not the upstream full datasets. The physical GPU comparison now has three measurements per size; two new order-reversed runs are pinned to one binary, which is not rebuilt from the current worktree.
4. **Demo risk:** Avoid a live promise of ML acceleration or GPU speedup. Use a verified solver path, disclose scope and measured limits, and show the fallback behavior.

## Mathematical review

1. **Core numerical foundation work has broad test coverage**, including sparse IPM, PDLP crossover, adaptive-ρ ADMM, iterative refinement, numerical diagnostics, verifier checks, and classifier tests. SQP now uses the limited-memory BFGS Hessian with box bounds in its QP subproblem (F-18); added targeted KKT, tiny-step, active-set, and callback-adversarial cases. API/JSON KKT components are present (F-19). The full suite must be rerun after these latest changes.
2. **Time-limit semantics are mathematically/reporting relevant.** A time-limited MIP cannot be reported as proven optimal merely because the root happened to close the gap after its advertised budget. Common absolute deadlines now reach root/iteration solvers and preserve `ResourceLimit`; long indivisible preprocessing/root operations can still overrun, so the strict runtime envelope remains unverified.
3. **GPU QP equivalence is narrower than an accelerated ADMM update.** A correct `P*x` residual kernel and matching final solution do not establish that the GPU computes the specified `(P + rho I)^{-1}` x-update. The latter remains CPU work.
5. **Large QP convexity checks now avoid dense allocation but remain conservative.** Sparse LDL and a fill cap separate proven indefinite from numerically indeterminate cases. QPLIB_8515 is still reported `Unsupported` when near-zero pivots cannot be certified (F-23).
6. **GPU crossover evidence is inconclusive beyond the measured range.** Three runs now cover the four tested sizes, including two runs in opposite instance orders; each shows slower end-to-end GPU time. This does not establish a universal absence of crossover or provide source-current randomized timing. Avoid extrapolating a threshold.

## ML expert review

1. **Dataset size and coverage are not sufficient for generalization.** The initial collection yielded only 8 populated logs; a corrected 8-instance corpus has 64 labels from 3 informative instances. The corrected remaining 72-case run yielded no labels because most roots timed out or exited. The existing graph-level split has six train graphs and one each for validation/test.
2. **The held-out metrics are degenerate.** All-zero labels make NDCG 1.0 non-informative; Kendall metrics are undefined or zero. Do not use those as model-quality evidence.
3. **Labels and deployment gate do not align yet.** Logs are generated from strong-branching decisions, but no logged/solved instance crossed the >200 candidate activation gate required for production inference.
4. **Model deployment requirements remain open.** Current export is float ONNX (20,776 bytes); int8 quantization and C++ parity for that artifact are not demonstrated. Current C++ parity covers the specialized scorer on a fixed graph fixture, not a broad distribution of collected graphs.
5. **Recommended evaluation:** keep instances disjoint; include non-degenerate labels; stratify candidate count and instance family; compare ranking metrics and solver outcomes; measure node count, wall time, inference overhead, and fallback rates; report multiple seeds and confidence intervals.

## Business review

1. **No validated customer workflow or willingness-to-adopt evidence is in this implementation evidence.** SIH demonstration value is present, but commercial demand and support burden remain unvalidated.
2. **Performance cost is visible:** current RTX 2050 GPU PDLP is slower than CPU PDLP on every measured case; hardware-specific deployment should therefore remain opt-in and presented transparently.
3. **Reliability/support risk:** the final pinned local MIPLIB sweep shows four verified optimal and four verified infeasible outcomes under 15 seconds; most rows hit iteration/resource limits, four are invalid models, one has numerical failure, and one exceeded the parent watchdog. The corrected training collection yielded no records from its 72 remaining instances. The final-binary QPLIB sweep reports 11 instances as unsupported by the KKT fill budget, three as limited, and four verified optimal. Users need truthful supported-instance boundaries and reproducible performance data.
4. **Commercial benchmark comparison must be auditable.** Published Mittelmann entries are wall-clock references without objective values and have sparse exact-name overlap with the selected suite. Separate locally reproduced free-solver comparisons from literature tables; match instances, hardware, tolerances, presolve settings, and versions before making relative claims.

## Industry-grade software review

1. **Deadline enforcement still has non-preemptible work units**, as described in F-04/F-17. It affects service-level predictability and safe orchestration.
2. **Continuous integration evidence:** the latest registered CTest run is 79/79; this is a clean local gate, while cross-platform and broader adversarial coverage remain necessary for release.
3. **Evidence reproducibility:** GPU tests ran on actual RTX 2050 hardware and passed. Two additional order-reversed runs are pinned to an exact binary hash, but the binary was not rebuilt from the current worktree, and timing lacks warm-up plus randomized interleaved CPU/GPU trials. Record these before using timing as a release claim.
4. **ML artifact provenance and release controls:** candidate ONNX remains in `/tmp` and is not shipped, correctly avoiding promotion of an unvalidated artifact. Keep model, feature schema version, training provenance, and parity report tied together if/when a model is promoted.
5. **Workspace hygiene:** the working tree contains substantial pre-existing and current uncommitted changes, generated datasets, and build directories. Review the final diff and ignored/untracked data before any commit or release; no commit has been made as part of this audit.
