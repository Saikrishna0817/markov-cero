# Research and literature notes

This folder preserves a **dated research workspace**, not a live implementation specification. Its algorithm, paper, dataset, metric and gap notes were generally written or verified against earlier source states. Some observations can be superseded by later code and [dated evidence](../../evidence/INDEX.md). Each note now carries a snapshot warning; follow its bibliography and source paths as historical leads, then check the current [capability register](../project/STATUS.md) before repeating a project claim.

## How to use these notes

- Use [consolidated knowledge](consolidated_knowledge.md) for a short synthesis and [paper references](research_paper_references.md) for the 204-entry bibliography.
- Follow topic directories such as `algorithms/`, `architectures/`, `concepts/`, `datasets/`, `metrics/`, `limitations/`, `research-gaps/` and `techniques/` when exploring a specific method or open question.
- Treat `[[wiki links]]` as research navigation, not as a promise that every cited implementation file still exists. Earlier audit, codebase, map and navigation notes were removed from the current checkout; historical references to them remain plain text and are recoverable through Git history.
- Use the [project status](../project/STATUS.md), [changelog](../../CHANGELOG.md) and [evidence index](../../evidence/INDEX.md) for current code and measurable claims.

The notes intentionally retain their original reasoning and dates. Updating the project's status does not rewrite past experimental observations or literature summaries into a false current-state narrative.
